# Local Vault Agent 한국어판

Obsidian의 노트를 검색하고 요약하거나 여러 문서를 정리하는 로컬 AI 플러그인입니다. 문서 변경은 비교 화면에서 승인한 뒤 적용하며, 변경 기록에서 실행 취소할 수 있습니다.

## 한국어판의 주요 변경

- 설정 설명, 채팅, 명령 팔레트, 초기 설정 및 주요 도구 이름을 한국어로 표시합니다.
- 화면 언어를 한국어와 영어 중에서 선택할 수 있습니다. 언어 변경 후 플러그인을 다시 로드하세요.
- 모델의 기본 답변 언어를 한국어로 설정했습니다.
- 첫 일반 채팅에서 로컬 모델 서버를 콘솔 창 없이 자동으로 시작합니다.
- 공급자 영역에서 엔진 실행 파일 경로를 지정할 수 있습니다.
- 채팅 모델 영역에서 GGUF 파일 경로를 지정하고 다른 모델로 변경할 수 있습니다.
- 기존 Ollama 및 OpenAI 호환 서버 연결 기능을 제공합니다.

## 기준 환경

이 배포판은 다음 환경을 기준으로 구성했습니다.

| 항목 | 기준 |
| --- | --- |
| 운영체제 | Windows |
| GPU | NVIDIA RTX 4070 Ti 12GB |
| 실행 엔진 | llama.cpp의 llama-server |
| 모델 | DNA 3.0 9B Q4_K_M GGUF |
| 공급자 | OpenAI 호환 |
| 로컬 서버 주소 | http://127.0.0.1:18081/v1 |
| 초기 모델 이름 | DNA3.0-9B |
| 자동 시작 서버 컨텍스트 | 최소 16,384토큰 |
| 검색 기본값 | 키워드 검색 |

다른 GGUF 파일도 지정할 수 있습니다. 모델을 실행할 수 있는지와 도구 호출을 지원하는지는 해당 모델 및 llama.cpp 버전에 따라 달라집니다. 자동 시작은 Windows 데스크톱의 위 로컬 서버 주소에서 지원하며, 실행 파일은 llama-server의 명령행 옵션을 지원해야 합니다.

## 설치

1. 설치용 local-vault-agent 폴더를 사용할 Vault의 .obsidian/plugins/ 아래에 복사합니다.
2. Obsidian을 열고 설정 → 커뮤니티 플러그인에서 Local Vault Agent를 활성화합니다.
3. 설정 → Local Vault Agent에서 공급자, 엔진 경로, 모델 경로를 확인합니다.
4. 채팅을 열고 메시지를 보냅니다. 모델이 로딩되면 첫 질문을 처리합니다.

플러그인은 Vault별로 설치합니다. 처음 사용할 때는 테스트 Vault에서 문서 변경과 실행 취소를 확인하세요.

## 엔진과 모델 경로

공급자 아래의 엔진 실행 파일 경로에는 llama-server.exe의 절대 경로를 입력합니다. 엔진 배포본의 DLL 파일도 실행 파일과 함께 준비해야 합니다.

채팅 모델 영역의 GGUF 모델 경로에는 사용할 모델 파일의 절대 경로를 입력합니다. 경로를 입력하면 파일 이름에서 .gguf를 뺀 이름을 채팅 모델 이름으로 설정합니다.

| 경로를 비워 둔 항목 | 사용하는 기본 위치 |
| --- | --- |
| 엔진 | 플러그인 폴더/engine/llama-server.exe |
| 모델 | 플러그인 폴더/models/DNA3.0-9B.Q4_K_M.gguf |

기존에 엔진과 모델을 보유하고 있으면 해당 파일을 그대로 지정할 수 있습니다. 현재 버전에서는 누락 파일을 자동 다운로드하지 않습니다. 파일이 없으면 경로 확인 메시지를 표시합니다.

공급자를 Ollama로 선택하면 Ollama의 서버 주소와 등록된 모델 이름을 사용합니다. 외부 OpenAI 호환 서버를 사용하는 경우에는 그 서버의 주소와 모델 이름을 지정합니다.

## 자동 실행과 모델 변경

첫 일반 채팅에서 서버 연결을 확인합니다. 이미 서버가 실행 중이면 선택한 모델 이름을 확인한 뒤 연결합니다. 서버가 없으면 지정한 엔진과 GGUF로 서버를 시작합니다.

이 플러그인이 시작한 서버는 엔진 경로, 모델 경로 또는 모델 이름을 바꾼 후 다음 일반 채팅에서 재시작됩니다. 플러그인을 종료하거나 비활성화하면 해당 서버도 종료됩니다. 외부에서 실행한 서버의 모델을 변경하려면 그 서버의 설정을 바꾸어야 합니다.

처음 모델을 로딩할 때는 응답까지 시간이 걸릴 수 있습니다. 컨텍스트와 모델 크기가 커질수록 메모리 사용량이 증가합니다.

## 검색과 문서 변경

기본 검색은 키워드 검색입니다. 의미 검색을 사용하려면 연결한 서버에 임베딩 모델을 준비하고 설정에서 의미 검색을 켜세요.

문서 생성 및 수정 요청은 변경사항 비교와 승인을 거쳐 적용됩니다. 변경 기록에서 승인한 작업을 확인하고 실행 취소할 수 있습니다. 자동 승인 설정을 켜면 승인 창을 생략하므로 원하는 동작인지 확인하세요.

## 업데이트와 복구

업데이트 전에 기존 빌드와 data.json을 백업합니다. 새 main.js, manifest.json, styles.css를 플러그인 폴더에 복사하고 Obsidian을 다시 시작합니다. data.json에는 개인 설정이 저장됩니다. engine 및 models 폴더를 유지하면 기존 파일을 재사용할 수 있습니다.

문제가 발생하면 플러그인을 비활성화하고 백업한 빌드와 설정을 복원합니다. 연결 오류는 서버 주소와 모델 이름을, 실행 오류는 엔진 경로와 DLL 및 모델 파일을 확인하세요. 컨텍스트 초과 오류가 발생하면 새 대화에서 대상 문서를 줄이거나 서버의 컨텍스트 설정을 조정하세요.

## 개발과 검증 범위

Node.js 환경에서 의존성을 설치하고 빌드합니다.

```powershell
npm.cmd ci
npx.cmd tsc -noEmit -skipLibCheck
npx.cmd eslint src
node esbuild.config.mjs production
npm.cmd test
```

현재 자동 테스트 401개가 통과했습니다. DNA 3.0과 llama.cpp 조합에서는 메모리 테스트 Vault를 사용해 한국어 검색, 문서 읽기, 두 문서 통합 및 생성 승인, 수정 거절, 생성 실행 취소를 확인했습니다.

일부 상세 오류와 도구 원본 결과에는 영어가 남아 있습니다. 모든 모델의 도구 호출 호환성과 모든 Obsidian 화면 동작을 검증한 상태는 아닙니다. 누락 파일 자동 설치는 아직 구현되지 않았습니다. 설치용 ZIP은 이 저장소의 local-vault-agent_kr.zip에서 받을 수 있습니다.
